# v1.0.0 · G2rain（谷雨）基础设施管理微前端应用

`g2rain-infra-app` 是 G2rain（谷雨）开源智能体平台中的基础设施管理微前端子应用。它交付发号器、字典用途与字典项、地区语言和国际化消息的管理界面，并通过动态资源路由和 qiankun 生命周期接入 `g2rain-main-shell`。领域数据、编号算法与服务端规则仍属于 `g2rain-infra`；认证、网关和全局子应用编排分别由 IAM、Gateway 和 main-shell 负责。本组件不代表整个平台能力或其所有可用状态。

## 构建、运行与镜像

项目版本为 `1.0.0`，要求 Node.js 22+、npm 和（构建容器时）Docker。`npm ci --legacy-peer-deps` 安装锁定依赖，`npm run build` 执行 TypeScript 类型检查和 Vite 生产构建；本仓没有独立 `test` 或 `lint` script。容器复用根目录 Dockerfile 与 `build.sh`：构建阶段为 `node:22-alpine`，最终运行时为 `openresty/openresty:alpine`，入口 `/docker-entrypoint.sh`，声明端口 `8080`，运行时默认 `SERVER_PORT=80`。

- 镜像：`ghcr.io/g2rain/g2rain-infra-app`。
- 标签：稳定版 `1.0.0` 与可追溯的 `sha-<完整提交 SHA>`；不创建或更新 `latest`。
- OCI 元数据：title、description、source、url、version、revision，以及与仓库 LICENSE 一致的 `Apache-2.0`。
- 发布顺序：先按 `feature/* → develop → main` 合入并验证本版本内容，再在该 `main` 提交推送 `v1.0.0`。工作流仅构建和推送镜像，不创建 GitHub Release 或部署服务。

## 镜像内容与密钥边界

最终镜像含 Vite `dist/`、OpenResty 配置与启动脚本、Lua 签名代码和离线 luaossl；不含 `lua/keys/`。生产环境须将 `public-key.der`、`private-key.der`，以及需要时的 IAM key-id/公钥文件，通过只读 Secret/Volume 挂载到 `/usr/local/openresty/nginx/lua/keys/`。`.dockerignore` 不会隐藏已跟踪文件，维护者仍须在公开仓库前检查是否存在凭据。

当前已跟踪 `.env.production` 会在构建时进入 Vite 输入并写入浏览器 Bundle；其中的 demo URL 和应用配置不是密钥，但任何未来写入的 Token、私有地址或生产凭据都会随镜像公开，必须在构建前人工移除或改为运行时注入。`lua/config.lua` 还包含默认 key-id；它不是私钥，但生产环境应核对其是否对应已注入密钥和实际 IAM 配置。

## 验证状态与限制

本次发布准备应验证 YAML、JSON、Shell、Dockerfile 与文档一致性，并运行 `npm run build`。Docker 可用时还应构建镜像并检查 `dist/`、Nginx、Lua 文件与空的密钥目录；GHCR 推送、匿名拉取、浏览器联调、真实 IAM/Gateway、Secret 挂载和实际部署验证均须以 Actions 记录和目标环境验收为准。首次成功推送后，如需匿名拉取，在 Package settings → Change visibility → Public 公开包；若已有包推送被拒绝，先在 Package settings → Actions access 和组织 Packages 策略中确认本仓写权限。
